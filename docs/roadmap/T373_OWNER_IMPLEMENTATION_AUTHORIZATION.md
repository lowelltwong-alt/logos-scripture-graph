# T373 Owner Implementation Authorization

T373 records the owner's selection of `T373-A`: authorize a future `T374` route-isolated, output-changing pilot only for the parent-only `1Cor.8.1-1Cor.10.33` epistle argument target.

The machine-readable record is:

- `.ai/control/t373_owner_implementation_authorization.yaml`

## What Is Authorized

- `T374` may implement the exact parent-only `1Cor.8.1-1Cor.10.33` pilot.
- The parent span may be used as the output chunk boundary only for that exact pilot.
- Route behavior may change only for that exact target.
- The future implementation PR must prove non-target identity and run same-baseline evaluation.

## Child Span Rule

Child spans are not bad by nature. They can be faithful when they are necessary, reviewed, explicit, and owner-promoted.

Child spans remain disallowed for `T374`. A later child-span decision would need exact proposed spans, reviewed child-span gold or equivalent governed evidence, necessity rationale, theological assumptions avoided, owner promotion, decision-register update, and validators/tests.

## What Is Not Authorized

T373 does not authorize child spans, preferred readings, source-tradition preference, graph edges, retrieval truth, embeddings, vectors, evaluator changes, boundary imports, broader epistle generalization, whole-Bible output passes, or any hidden theological system.

## Required T374 Proof

Before a T374 merge, the implementation must provide:

- exact T373 authorization record
- task scope for output-changing paths
- parent-only scope proof
- non-target identity proof
- same-baseline evaluation
- changed-output manifest
- decision-register update
- validators/tests
- no-context audit surface
- validated handoff

T374 must fail if child spans are added, route behavior leaks outside `1Cor.8.1-1Cor.10.33`, non-target output changes, source metadata becomes authority, or graph/retrieval/vector truth is generated.

## Future Owner Gates

T373 also adds `.ai/control/owner_decision_option_presentation_policy.yaml` so future owner gates must show the serious faithful options, repercussions, risks, recommendation, non-authorizations, validators, and downstream effects before the owner decides.
