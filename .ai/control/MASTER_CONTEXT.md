## System purpose

Build a **governed semantic substrate** for a Bible knowledge graph — not an agent runtime. This repo owns source truth, passage identity, translation witnesses, boundary evidence, chunk policies, schemas, validation, and release artifacts. Retrieval, agents, and UI consume **derived** artifacts through contracts.

**Quality bar:** A chunk or graph edge must be auditable to raw source, boundary evidence, policy version, and trust zone. Generic token-window RAG on Bible text is explicitly rejected.

## Non-negotiable architectural decisions

### 1. Three-plane separation

- **Knowledge plane:** manifests, passages, witnesses, boundaries, chunks, graph claims
- **Control plane:** roadmap, handoffs, schemas, validation, this file
- **Execution plane:** separate agent runtime (future); never source of truth

### 2. Raw immutability (ADR-0002)

- All downloaded source files live under `data/raw/` only
- Never hand-edit raw files; never put processed files in raw
- Every raw family has a manifest + checksum before ingest

### 3. Chunks are derived (ADR-0003)

- Chunks are retrieval objects with boundary evidence — not canonical text
- Rebuildable from canonical + policy + boundary claims
- LLM-proposed boundaries are **candidates**, never canonical without review

### 4. Sidecar ingest, not flattened text

- USFM embedded features (`\w`, `\f`, `\x`, structural markers) become typed sidecars
- `TranslationWitness.text` must never contain raw USFM markup
- Editorial crossrefs (`\x`) stay `editorial_cross_reference` — not auto-promoted to theological graph edges

### 5. Boundary stack for chunking

Chunking uses a **boundary hierarchy**, not token windows alone:

```text
book → source/license → USFM structure → sentence → literary genre → source-language → token budget
```

- Verse boundaries are **weak** (address units, not meaning units)
- USFM boundaries are **translation formatting evidence**, not ancient canonical boundaries (`is_canonical_ancient_boundary: false`)
- Hebrew/Greek boundaries may override English convenience **after review** (future ADR-0006)

### 6. Trust zones and assertion modes

- **Asserted** vs **inferred** vs **candidate** must never be mixed in one artifact
- New relationship predicates require schema/registry registration
- Production graph edges require evidence refs + provenance + confidence

### 7. Canon is explicit, never implicit

- Multi-tradition corpus (WEB includes deuterocanonical books) requires `CanonProfile` metadata on passages
- Ingesting a book ≠ asserting canonical status for any tradition
- Publishing `data/canonical/` without canon metadata = implicit theology decision (**forbidden**)

### 8. Multilingual path (phased)

- Phase 2 (English WEB ingest) does not block on Hebrew/Greek
- Strong-tagged `WordToken` records are the v0 alignment bridge
- Source-language witnesses (WLC, SBLGNT, LXX) are separate schemas — not merged into English witnesses
- Mature quality requires TextSpan + AlignmentRecord + ancient boundary claims

## Identity chain (target state)

```text
ScriptureWork
  → ScripturePassage (language-agnostic OSIS address)
     → TranslationWitness / SourceLanguageWitness
        → TextSpan (verse, sentence, paragraph, poetry line, clause)
           → BoundaryClaim (scored evidence)
              → RetrievalChunk (derived, policy-versioned)
                 → ContextPacket (required discourse context)
                    → RelationshipObject (asserted/inferred/candidate)
```

**Current gap:** TextSpan, ContextPacket, SourceLanguageWitness, AlignmentRecord not yet implemented. Do not skip to embeddings or graph edges.

## Engineering principles

1. **Deterministic pipelines** — same raw input + manifest + policy version → same output
2. **Validation before merge** — CI runs control-plane + handoff + pytest gates
3. **Provenance everywhere** — source_id, sha256, license, generation_method on derived records (canonicalize via ProvenanceRecord in future)
4. **Small reviewable diffs** — prefer ADR + schema stub over silent refactor
5. **Agent handoffs mandatory** — chat transcripts are not project state
6. **Human gates master context** — agents recommend; humans promote

---

## Explicit rejections

- Token-window-only chunking on Bible text
- Treating chapter/verse as discourse boundaries
- Promoting editorial `\x` crossrefs to `quotesFrom` / `fulfills` without review
- Mutating `MASTER_CONTEXT.md` or `MASTER_CONTEXT.lock.yaml` without human approval
- Skipping handoff / PROJECT_STATUS updates after non-trivial work
- Public release of canonical data before CanonProfile ADR
