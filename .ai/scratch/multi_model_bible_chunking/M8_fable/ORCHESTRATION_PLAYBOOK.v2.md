# M8_fable Orchestration Playbook — v2 (2026-09-13)

This playbook records how the campaign runs its agents and subagents, and what the receipts say worked, so the method can be re-run and
improved. It was written at the owner's direction (ledger OW-14, 2026-09-11, verbatim there).

- **Scope.** The M8_fable whole-Bible chunking marathon, as practiced through Ezekiel's FIXUP-3 wave and S4's launch.
- **Status.** Candidate-only and non-authorizing. Owner directives, the error-pattern ledger, the close gate and the controlling agent's
  rulings outrank anything here. This file describes them and points to them; it never replaces them.
- **History is append-only.** A version is never rewritten. A change is a new version (v2, v3, ...) with a "Changed since" section naming
  the learning-log entries that justify it. The resume prompt names the current version.

## Changed since v1

v1 was written before FIXUP-3 was applied. Five learning-log entries justify this version:

- **L-0012 (wording, failed).** A brief that offers example sentence shapes as literal wording converges across authors. FIXUP-3's brief
  supplied a mark-disclosure shape whose tail already stood in 6 rows; one author used it in four more and the applied corpus failed the
  HARD ngram7 gate at 10. → §3 step 3a, §4.
- **L-0013 (tool, mixed).** A tool that pins every suite member to ONE install receipt breaks when the campaign later repairs one member.
  → §3 step 10, §4.
- **L-0014 (control, worked).** The control is now an installed tool, `SP\campaign\_brief_shape_headroom.py`, whose install refuses unless
  its selftest reproduces the historical failure. Running it also caught the orchestrator stating row counts it had read rather than
  measured. → §3 step 3a, §5, §6.
- **L-0015 (model, worked).** An Opus execution ordered to repair a Sonnet execution's rows cured the gate, ran the installed suite before
  delivering, and disclosed three byte-corrections beyond its orders. It cost 47% more than the execution it replaced. → §1.2, §4.
- **L-0016 (wording, worked).** A relaunch that hands the author the measurement — the failing artifact by digest, the exact offending
  strings, the author's own rows carrying them, and the measured headroom of every shape the earlier brief supplied — produced a targeted
  re-execution and surfaced two residual risks no "vary your wording" instruction would have. → §3 step 8, §4.

## 2. The loop for a hard-track book (Ezekiel as run)

```
Phase 0 staging (toolkit, inventories, verse maps; cure claims on the toolkit)
  -> strategy (Fable) -> writer wave (authors by part) -> S1 spot review (distinct)
  -> controlling execution #eN (Fable rulings on the review's findings)
       -> deterministic corpus-wide sweeps (CWO) -> tool fixes, staged and installed by receipt
       -> fix-up wave: orders -> brief (example wording MEASURED against the corpus) -> pin check
            -> budget test -> launch -> land -> transcript audit -> apply -> suite -> coverage
            -> a gate failure is a RELAUNCH of the part that caused it, with the measurement in the message,
               and the earlier apply's outputs are superseded, never overwritten
       -> fresh distinct check S(N+1) on the applied rows
       -> repeat #eN / fix-up / S until the distinct check reads rows readiness fit=true
  -> rows cure claims (artifact-bound verification + the distinct checker's verdict)
  -> primaries (blind lanes -> peer -> boss -> author wave -> guarded apply)
  -> finalize: two-stage Fable final check + a second independent Fable review of flagged regions
  -> close gate (all items) -> OW-12 project status update -> OW-14 playbook and learning-log update -> next book
```

Ezekiel's actual path so far: FIXUP-1 → S2 → #e9 → FIXUP-2 → S3 → #e10 → CWO-EZ-23 and CWO-EZ-22 coverage → TOOLFIX-5 → FIXUP-3 (applied
twice; the first apply failed its ngram7 gate and p03 ran again on Opus) → S4 (launched on Fable 2026-09-13). Each step is logged in
`SP\Ezek\freeze\CYCLE_STATE.md`.

## 3. The launch protocol (what makes subagent work land)

1. **Generate, never hand-transform.** Orders come from the rulings text by a builder, and the builder refuses a disagreement. Briefs carry
   ruled text cut verbatim between fixed markers. Example: `SP\Ezek\_build_fixup3_orders_ezek.py` refused #e10 S3-03's misstated
   exact_spans (ledger E-03-i-e10-S3-03).
2. **Preview, then write.** The brief builder has a preview mode; the orchestrator reads the preview before writing the pinned brief.
3. **Pin check MATCH before every launch.** `SP\campaign\_brief_pin_check.py --brief <brief>` (OW-11-l).
3a. **Measure any example wording before the brief offers it (L-0012, L-0014).** `SP\campaign\_brief_shape_headroom.py --book <Book>
   --corpus <the corpus the wave writes into> --shapes <shapes.json> --parts <the wave's part count>` must read SAFE. A gram already
   standing in R rows fails once R + parts reaches the ngram7 gate, so a shape is SAFE only when `gate - 1 - R >= parts`; a shape it
   REFUSES is dropped or given as the ruled form without literal wording. The tool imports the book's installed `ngram7.py` rather than
   copying its tokenization, because a private tokenizer drifts from the gate it predicts.
4. **The launch message** carries, in this order: the E-13 research-context preamble; the OW-11 authority paragraph with the owner's
   verbatim answers (OW-11-h); the E-19 no-check line and exact-path law; the pinned-input rule; the scoped validator verdict; the verdict
   wording (#e8 T6-02); and the job, with the brief's digest.
5. **Budget test** at the measured maximum before every launch: census + N × max < ceiling. Otherwise the owner check-in comes first.
6. **Gate check before a gated launch.** Where a ruling states conditions (GATE-E10's `s4_may_launch`), a script decides each clause from
   the artifacts, binds every report to the corpus digest, and refuses if the ruling's own wording no longer contains the sentence the
   script implements (`gate_e10_s4_check.py`).
7. **Record at launch:** a transcript-map entry through `SP\campaign\_guarded_json_patch.py`, then one CYCLE_STATE entry, then a durability
   checkpoint (state input → CURRENT_STATE → resume prompt generated, read back and verified).
8. **On completion:** save the record from the runtime notification by script; run the in-flight pin guard; land (form, local tiling,
   normalizer), taking the ordinal from the agent's own record; preserve transcripts; **audit the transcript** — count the tool calls, prove
   no listing, glob or existence check stands on a line carrying a tool call, and prove no write landed inside the worktree; then write a
   CYCLE_STATE landing entry whose observations are checked against the record, not copied from it.
9. **A decline** is recorded (`REFUSED_NO_DELIVERABLE`) and relaunched once with a context paragraph answering its points. A second decline
   goes to the owner. **A gate failure** is relaunched with the measurement (L-0016): the failing artifact by digest, the exact offending
   strings, the author's own rows carrying them, and the measured count of every shape the earlier brief supplied.
10. **Tool changes are plumbing or they are rulings.** Plumbing is staged with a preimage, a diff the distinct checker reads, an install
    receipt and a regression that reproduces existing outputs byte for byte. A tool that verifies another tool's digest names **the receipt
    per member**, not one receipt for all (L-0013).
11. **The distinct check** reads the applied rows. Cure claims are written only on its fit=true verdict in the ACCEPT form.

## 4. What the evidence says so far

Each line points to its record. The learning log carries the structured entries, and the metrics file carries the counts.

- **Worked: generating artifacts from sources.** Hand-transformed records caused two errors in Lamentations (a fabricated provenance
  citation; launch messages disagreeing with the orders they named). In Ezekiel, builders that refuse disagreements caught a misstated
  ruling span before any author saw it (E-03-i-e10-S3-03).
- **Worked: the pin check before launch.** A stale pinned digest had shipped to all eleven FIXUP-1 parts before the control (OW-11-l).
- **Worked: the authority paragraph in the launch message.** Ezekiel's first author p01 refused without it; its relaunch with it landed.
- **Worked: auditing transcripts at landing.** It found p08's Test-Path and ls, which its self-report denied (OW-10). p03 #e2's audit, by
  contrast, confirmed its self-report: 24 tool calls, no listing on any tool line, its single write in the session scratchpad.
- **Failed: example wording in a brief (L-0012).** FIXUP-3's brief offered three mark-disclosure shapes as literal sentences. Shape A's tail
  already stood in 6 rows, leaving room for three; one author used it in four and the applied corpus failed the HARD ngram7 gate on three
  sub-grams, which also put CWO-EZ-07 at NOT_COVERED. The cost was one re-execution (314,747 tokens), a second apply and two plumbing
  patches. The control is §3 step 3a.
- **Failed, same class: figures the orchestrator read rather than measured (L-0014).** A CYCLE_STATE entry stated two shapes stood in "4 and
  3 rows, all p03's"; measured, each stood in 4 and one predated the wave. Corrected in place before any digest was pinned. A figure that
  sounds measured is measured, and the record names the tool that measured it.
- **Mixed: Sonnet authors on FIXUP-3.** Six parts launched on claude-sonnet-5 under the strict E-19 wording: p01 declined twice; five
  landed with clean form; p02, p07 and p08 each had an E-19 lapse, p08's undisclosed; p03 skipped the installed suite, which would have
  caught the gate failure before delivery. This led to OW-13.
- **Worked: Opus repairing another model's rows (L-0015).** p03 #e2 on claude-opus-5 replicated the gate's tokenization from the installed
  tool, measured the background counts, wrote twelve disclosures from its own rows' bytes reusing no supplied shape, ran the installed suite
  before delivering, and disclosed three byte-corrections beyond its orders. 47% more tokens than the execution it replaced; suite RED → GREEN.
- **Worked: superseding rather than overwriting.** The first apply's rows, manifest, suite and coverage reports moved to
  `repair\superseded_v6_run1\` with a NOTE holding every digest before and after, so the failure remains inspectable.
- **Open: the residual the gate does not yet catch.** Two seven-word families stand in 9 rows each against a gate of 10, measured over
  rows_v6. Headroom is 0: one more row anywhere turns the HARD gate RED. S4's FQ3-02 puts it to the checker.
- **Open: model versus wording in declines.** Every Ezekiel receipt with outcome REFUSED_NO_DELIVERABLE is a claude-sonnet-5 execution.
  Model and wording are confounded; test by comparing refusal rates across models and wordings in the metrics.
