improved. It was written at the owner's direction (ledger OW-14, 2026-09-11, verbatim there).

- **Status.** Candidate-only and non-authorizing. Owner directives, the error-pattern ledger, the close gate and the controlling agent's
  rulings outrank anything here. This file describes them and points to them; it never replaces them.
- **History is append-only.** A version is never rewritten. A change is a new version (v2, v3, ...) with a "Changed since" section naming
  the learning-log entries that justify it. The resume prompt names the current version.

## 2. The loop for a hard-track book (Ezekiel as run)

```
Phase 0 staging (toolkit, inventories, verse maps; cure claims on the toolkit)
  -> strategy (Fable) -> writer wave (authors by part) -> S1 spot review (distinct)
  -> controlling execution #eN (Fable rulings on the review's findings)
       -> deterministic corpus-wide sweeps (CWO) -> tool fixes, staged and installed by receipt
       -> fix-up wave: orders -> brief -> pin check -> budget test -> launch -> land -> apply -> suite -> coverage
       -> fresh distinct check S(N+1) on the applied rows
       -> repeat #eN / fix-up / S until the distinct check reads rows readiness fit=true
  -> rows cure claims (artifact-bound verification + the distinct checker's verdict)
  -> primaries (blind lanes -> peer -> boss -> author wave -> guarded apply)
  -> finalize: two-stage Fable final check + a second independent Fable review of flagged regions
  -> close gate (all items) -> OW-12 project status update -> OW-14 playbook and learning-log update -> next book
```

Ezekiel's actual path so far: FIXUP-1 → S2 → #e9 → FIXUP-2 → S3 → #e10 → CWO-EZ-23 and CWO-EZ-22 coverage → TOOLFIX-5 → FIXUP-3 → S4
(next, on Fable). Each step is logged in `SP\Ezek\freeze\CYCLE_STATE.md`.

## 3. The launch protocol (what makes subagent work land)

1. **Generate, never hand-transform.** Orders come from the rulings text by a builder, and the builder refuses a disagreement. Briefs
   carry ruled text cut verbatim between fixed markers. Example: `SP\Ezek\_build_fixup3_orders_ezek.py` refused #e10 S3-03's misstated
   exact_spans (ledger E-03-i-e10-S3-03).
2. **Preview, then write.** The brief builder has a preview mode; the orchestrator reads the preview before writing the pinned brief.
3. **Pin check MATCH before every launch.** `SP\campaign\_brief_pin_check.py --brief <brief>` (OW-11-l).
4. **The launch message** carries, in this order:
   - the E-13 research-context preamble;
   - the OW-11 authority paragraph with the owner's verbatim answers (OW-11-h);
   - the E-19 no-check line and #e10 OPEN-ITEMS (b) in words;
   - the exact-path law, the pinned-input rule and the scoped validator verdict;
   - the job, with the brief's and orders' digests.
5. **Budget test** at the measured maximum before every launch: census + N × max < ceiling. Otherwise the owner check-in comes first.
6. **Record at launch:** a transcript-map entry through `SP\campaign\_guarded_json_patch.py`, then one CYCLE_STATE entry, then a
   durability checkpoint (state input → CURRENT_STATE → resume prompt generated, read back and verified).
7. **On completion:**
   - save the record from the runtime notification by script;
   - run the in-flight pin guard;
   - land (form, local tiling, normalizer; `SP\Ezek\_land_author_part_ezek.py`);
   - preserve transcripts (`_preserve_subagent_transcripts.v2.py`);
   - audit the transcript for writes outside scope, globs, listings and existence checks;
   - write a CYCLE_STATE landing entry whose observations are checked against the record.
8. **A decline** is recorded (`REFUSED_NO_DELIVERABLE`) and relaunched once with a context paragraph answering its points. A second
   decline goes to the owner.
9. **The distinct check** reads the applied rows. Cure claims are written only on its fit=true verdict in the ACCEPT form.

## 4. What the evidence says so far

Each line points to its record. The learning log carries the structured entries, and the metrics file carries the counts.

- **Worked: generating artifacts from sources.** Hand-transformed records caused two errors in Lamentations:
  - reconstructed receipts cited a launch record the orchestrator never opened, a fabricated provenance citation
    (`SP\Lam\final_check\receipt_amendments.v1.jsonl`);
  - launch messages disagreed with the orders they named, and the control `_check_launch_orders_agree.py` now compares them before any
    launch (`SP\campaign\finding_launch_orders_base_mismatch.v1.json`).
  - In Ezekiel, builders that refuse disagreements caught a misstated ruling span before any author saw it (E-03-i-e10-S3-03).
- **Worked: the pin check before launch.** A stale pinned digest had shipped to all eleven FIXUP-1 parts before the control (OW-11-l).
- **Worked: the authority paragraph in the launch message.** Ezekiel's first author p01 refused without it, and its relaunch with it
  landed (OW-11-h; `SP\Ezek\author\ezek_author_attempt_receipts.jsonl`).
- **Worked: auditing transcripts at landing.** It found p08's Test-Path and ls, which its self-report denied. A self-report is not
  sufficient (OW-10).
- **Worked: canonical resume clauses.** A rule carried only in the working log went stale for a day, when the 15M budget sentence
  outlived two budget answers (OW-11-n).
- **Mixed: Sonnet authors on FIXUP-3.** Six parts were launched on claude-sonnet-5 under the strict E-19 wording.
  - p01 declined twice before any tool call.
  - Five landed with clean form.
  - p02, p07 and p08 each had an E-19 lapse, and p08's was undisclosed.
  - p03 skipped the installed suite.
  - This led to OW-13: substantive authoring moves to Opus, Fable checks it, and Sonnet takes only bounded work (CYCLE_STATE, FIXUP-3
    batches 1-4 and the p01 entries).
- **Open: Opus authors.** The first execution is p01 #e3, launched 2026-09-11. Its outcome, cost and S4's verdict on its rows go in
  the learning log.
- **Open: model versus wording in declines.** Every Ezekiel receipt with outcome REFUSED_NO_DELIVERABLE is a claude-sonnet-5
  execution: toolkit review T1 #e1, author p01 #e1, and FIXUP-3 p01 #e1 and #e2. The first two lacked the owner's exception in their
  launch messages. The last two cited both an authority they could not verify and the no-listing lines, so model and wording are
  confounded. Test by comparing refusal rates across models and wordings in the metrics.

## 6. Iteration protocol (OW-14)

- **When.** At every wave landing, every distinct-check landing, every controlling-execution landing, and every book close.
- **Learning log.** Append one or more entries to `M8\orchestration_learning_log.v1.jsonl`. Never edit an entry; a correction is a new
  entry with `supersedes`. Schema `m8_orchestration_learning.v1`:
  - `id`, `date`, `book`, `stage`;
  - `element`: one of role | model | lane | topology | control | tool | wording | budget;
  - `observation`, `evidence_refs[]`, `metric{}`;
  - `verdict`: one of worked | failed | mixed | open;
  - `recommendation`, `supersedes`.
- **Metrics.** Run `python SP\campaign\_orchestration_metrics.py --write`. It groups receipts by book, lane and model ordered.
- **Versions.** When the evidence changes a recommendation in §1-§5, write the next playbook version with "Changed since vN" naming the
  entries, and point the resume prompt at it.
- **Gate.** Close-gate item 18 checks this at every book close.
- **DAD.** Major lessons also go to DAD's lesson intake (campaign memory: dad-lesson-routing-rule).
